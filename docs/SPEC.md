## 问题陈述

一个项目的工作通常分散在多条 Codex 会话中。会话列表无法充分说明工作的前因后果、各条研究路线、失败后的修复以及结果验证。会话还可能被多次恢复，创建到最后更新之间的跨度不能代表真实活动时长。

用户需要打开一个项目，了解它如何推进、哪些结论有原始依据、哪些关联只是模型判断，并能定位支持某条关系的具体记录。

## 解决方案

提供在 macOS 与 Windows 11 x64 本地运行的桌面应用，经 Codex app-server 读取当前用户的历史，将其规范化并保存到 SQLite。应用以项目为入口，提供工作流导航、时间线、关系图和会话详情；另提供可跨项目浏览的主题分组。平台差异由 CLI 解析、系统凭据和桌面打包适配处理。

首次打开项目先显示可用来源事实和结构关系。用户手动启动分析后，Codex 从结构化事实和必要来源内容生成总结及工作流名称；独立嵌入服务为会话总结和产物摘要生成向量；Jev 判断候选会话关系、执行阶段和结果，并为会话分配全局主题。候选信号本身不创建关系边。模型分析失败时，已有来源事实仍然可查看。

观察关系和推断关系始终保留独立来源标记。Jev 判断说明作为模型支持理由保存，但不要求程序再次验证引用来源。用户可以确认或拒绝推断关系。

## 实现决策

### 1. 模块边界

架构采用 React、TypeScript、Tauri、Rust 与 SQLite。

| 模块 | 责任 | 允许的依赖 |
| --- | --- | --- |
| React UI | 项目导航、时间线、关系图、详情、分析操作 | Tauri 提供的应用接口 |
| Tauri 入口 | 命令与事件桥接、桌面生命周期 | `codexflow-core` |
| `codexflow-core` | 索引、项目解析、事实提取、候选召回、主题归属、关系分组与应用查询 | domain、codex、jev、embedding、store |
| `codexflow-codex` | app-server 进程与连接、RPC、传输类型、能力适配 | domain |
| `codexflow-jev` | TypeSafe HTTP、认证与凭据访问、连接诊断、结构化决策到领域结果的适配 | domain |
| `codexflow-embedding` | OpenAI 兼容嵌入 HTTP、独立认证、连接诊断及向量响应校验 | domain |
| `codexflow-store` | SQLite、迁移、领域数据持久化 | domain |
| `codexflow-domain` | 项目、会话、事实、关系、主题及工作流的领域语义 | 不依赖上层模块 |

UI 经 Tauri 调用核心服务，不直接调用 app-server、Jev 或嵌入服务。core 不处理原始 JSON-RPC 或远端 HTTP 报文。store 不依赖服务传输类型，也不保存 API Key 明文。适配层必须先把外部数据转换为领域数据；各服务凭据独立保存在操作系统凭据库，macOS 使用钥匙串，Windows 使用 Credential Manager。没有受支持的系统凭据后端时，保存凭据必须失败，不得回退为明文文件。

关系图采用 `@xyflow/react` 与 `elkjs`。布局方向属于展示策略，不能改变关系语义，也不能仅因使用分层布局就假设所有语义关系构成 DAG。

### 2. 数据来源与协议

通过受应用管理的 app-server 子进程和标准输入输出读取数据，依次执行 `initialize` 与 `initialized`。应用记录实际二进制路径、版本及可用能力；不假设系统命令与桌面内置二进制相同。

列表显式枚举 `cli`、`vscode`、`exec`、`appServer`、`subAgent`、`subAgentReview`、`subAgentCompact`、`subAgentThreadSpawn`、`subAgentOther` 和 `unknown`。这是本次核验基线中的完整来源枚举；适配器负责兼容来源类型变化。普通历史采集不使用空来源列表代替“所有来源”。

分别以未归档和已归档条件读取，沿服务端不透明游标分页直到结束，然后按会话身份去重。列表完整与内容完整是两个不同条件。

会话身份使用 Codex Thread ID。会话 ID、会话所属项目标识、session 标识和路径不得互换。

已核验基线为 `codex-cli 0.150.1`，不把它宣称为已验证的最早兼容版本。默认协议具备会话列表、会话读取、临时会话、结构化最终输出及回合中断；回合分页、条目分页与项目接口属于实验能力。

历史读取契约：

1. 在支持时通过初始化能力显式启用实验接口，优先使用回合与条目分页。
2. 回合列表的默认条目摘要不能作为完整证据。提取完整内容时显式请求完整视图，或取得对应条目分页。
3. 条目分页可能因历史存储形态不支持而失败。适配器可使用经过契约测试的 `thread/read` 完整历史兼容路径。
4. 两条读取路径均不可用时保留会话元数据与可证明的结构关系，显示内容不可用，并排除需要缺失内容才能进行的分析。
5. 单条会话读取失败不阻塞其余可读会话；分页部分成功只形成部分内容状态，不冒充完整历史。
6. 缺少初始化或列表等最低元数据能力时，来源标为不兼容，显示升级或选择其他二进制的提示，并保留已缓存结果。
7. 不以私有 JSONL、内部数据库或截图解析作为静默后备路径。

实际历史存储与兼容读取矩阵必须在适配器交付时验证；本次模式核验不等同于真实历史端到端验证。

采集路径不得依赖 UI 截图。模型分析与来源历史读取必须区分，分析不能向用户原有会话追加回合。

### 3. 项目归属

同一 Git 仓库的主工作区与 worktree 合并为一个项目，但保留各会话的工作目录和工作区身份。相同远程地址的独立克隆不自动合并。

项目解析规则：

1. 区分 Codex 来源项目标识与 CodexFlow 本地项目身份。
2. 本地 Git 仓库以解析后的共享 Git 目录确认同仓库关系，以实际工作区根记录路径；远程地址只作辅助信息。
3. 来源项目标识可复用已确定且不冲突的归属，不能强行合并已证实为独立克隆的仓库。
4. 非 Git 项目按用户选择的真实根目录及目录组件边界归属，排除嵌套独立 Git 仓库。
5. 已删除路径优先使用此前已验证的归属；新发现但无法验证归属的会话保持未归属状态并说明原因。
6. 原生项目标识、Git 证据和路径之间发生冲突时显示归属诊断，不静默选择可能误合并的结果。

这收紧了草案中的“project_id 优先”建议，使其不违反用户已确认的 worktree 与独立克隆边界。

全局主题组不改变项目身份，也不把独立克隆合并为同一项目。每条会话仍归属于原项目；主题标签可以跨多个项目重复出现，项目内工作流仍单独计算。

### 4. 索引与存储

SQLite 位于应用管理的本机用户数据目录，保存项目、会话、回合、规范化条目、结构化事实、总结、关系、证据、工作流、成员关系和分析运行记录。最近选择的项目及用户显示偏好持久化；不要求向被分析项目写入数据。

来源证据继续存储来源定位、必要摘录及对应内容版本；Jev 推断关系另保存模型判断说明，不要求存在经程序复核的双侧证据指针。不能把服务传输类型直接保存为领域契约。Codex 认证仍由已配置的 Codex 处理，CodexFlow 不复制其秘密；Jev、文本与嵌入服务的 API Key 分别由用户提供并保存到操作系统凭据库，macOS 使用钥匙串，Windows 使用 Credential Manager。应用数据库只保存非秘密连接设置和凭据引用。
SQLite 另保存全局主题词表、每会话的人工/自动主题归属、主题归属置信度、嵌入向量、嵌入模型身份、内容摘要版本和来源版本。向量缓存只按当前来源内容摘要和嵌入配置复用；更换服务、模型或来源内容时重建相关向量。主题校准标签与关系校准样本使用独立数据结构，不与用户当前工作流修正混为一类。

索引契约：

- 重复索引相同来源得到相同实体和关系，不重复插入。
- 元数据完整性、回合完整性和条目完整性分别记录。
- 部分分页失败不会被当作来源记录删除；已提交数据继续可用，并显示不完整或过期状态。
- 来源变化使相关自动分析标为需要更新，不擦除用户裁决。
- 来源事实、自动分析与人工修正具有独立的更新职责。

首次打开时先读本地缓存，再启动一次来源刷新；后续由用户主动刷新。V1 不以持续文件监听或实时订阅作为必要功能。

索引运行区分待执行、执行中、完成、部分完成、失败和已取消。只有相关来源范围的完整列表成功后，才能判断此前缓存会话已不在列表中；此判断不自动删除缓存、证据或用户数据。

内容哈希、提取规则版本、各阶段模型配置与分析规则版本共同决定缓存是否可复用。Jev 缓存还包含规范化 Base URL、实际模型版本、问题定义及候选输入版本；Codex 总结或命名缓存不因仅修改 Jev 配置而失效。密钥不参与内容哈希或结果标识，仅轮换密钥不会重算已有语义结果。重启后未终结的运行标记为中断，用户可从已提交单元继续。

迁移使用事务并记录版本。迁移失败或发现更新版本的数据库时保留原数据，提供结构化错误；不得通过创建空库伪装为恢复成功。普通退出、来源不可用和分析失败均不清理人工修正。

### 5. 真实活动时间

会话使用创建时间、最后活动时间、多段活动区间和活动时长。不得以创建到最后更新的整个跨度冒充持续活动。

Turn 时间字段允许为空，因此“全部活动时长等于各回合时长之和”只在相关来源数据完整且有效时成立。

时间契约：

- 仅凭有效回合起止时间绘制完整活动区间；没有依据的空档保持空白。
- 有明确开始、尚未结束的回合显示进行中，已结束但缺少结束时间的回合显示时间不完整。
- 只累计来源提供的有效回合时长，并标识完整、部分已知或未知。
- 来源时间单位在适配层转换，内部统一时间语义。
- 异常时间不通过交换边界、补零或估算修复。
- 工作流内的并行活动可重叠；累计回合时长与墙钟经过时间分别解释。

Unix 秒与毫秒在适配层分别转换为内部 UTC 毫秒；界面默认使用系统时区。最后活动时间优先使用来源活动字段及已知回合活动时间，只有更新时间时标注其元数据属性，不将其作为活动结束证明。

只有一个有效 `durationMs` 而没有起止时间的回合可以参与已知时长累计，但不能凭此伪造时间线位置；只有起止时间而没有 `durationMs` 时可以绘制区间，但累计时长仍标为部分已知。回合经过时间不是纯模型计算时间，也不是用户实际工时。

### 6. 事实与会话总结

先提取来源条目中的文件修改、命令、分支和可定位文本等结构化事实，再构建分析输入。

Codex 临时会话生成覆盖目标、活动、结果、决定和问题的总结。总结是模型生成内容，不能替代来源执行状态或证明某条命令成功。Jev 不承担自由文本总结。

文件修改或命令执行事实与会话中的文字叙述保留来源差别。例如，“计划修改某文件”不能被提取为已发生的文件修改。

### 7. 关系与证据

结构关系包含 `FORKED_FROM` 和 `SUBAGENT_OF`，直接取自来源事实。

候选信号包括明确引用、共享文件或产物、相同分支名、更新时间接近、词语重合和向量相似，允许跨项目命中。候选信号只决定哪些会话对交给 Jev，不生成规则关系边，也不直接参与工作流分组。观察关系仍由来源事实产生。

已观测结构关系的置信度为 1.0。Jev `Choice` 返回的 `confidence` 是模型输出分数，并独立保存 `probabilities`；两者不得混为同一数值，也不宣称置信度是概率校准的正确率。边权综合关系类别、置信度和执行阶段；不使用统一的 0.70 硬门槛。

推断类型保留 `CONTINUES`、`IMPLEMENTS`、`FIXES`、`VALIDATES`、`INVESTIGATES`、`ALTERNATIVE_TO`、`SUPERSEDES`、`MOTIVATED_BY`、`RELATED`，并新增 `DEPENDS_ON`、`MODIFIES`、`REVIEWS` 和 `HANDOFF_TO`。每种有向关系定义自己的端点语义，例如评审关系从评审会话指向被评审工作；不能仅凭端点顺序或时间戳推断方向。无向关系按稳定标识排序。`RELATED` 和 `ALTERNATIVE_TO` 只保留为跨工作流联系，不参与工作流归组。

- Jev 对关系支持状态、类型、方向、执行阶段和结果进行结构化判断。TypeSafe `Choice` 不生成自由文本；界面按结构化答案组合关系说明，并明确它不是来源条目证据。
- 关系判定不要求单独的双侧证据选择请求或来源指针验真。候选会话当前可用的总结、产物摘要、事实和线索供 Jev 判断；程序仍校验返回端点、关系类型、方向、模型身份和输入版本。
- `REJECTS` 和 `UNKNOWN` 均不创建关系边。无支持关系时分别保存“无关系”或“无法判断”的版本化结果供去重；来源或配置变化后才重新判断。
- 执行阶段为 `PLANNED`、`STARTED`、`COMPLETED`。阶段越深入，边权越强。
- 执行结果为 `SUCCESSFUL`、`BLOCKED`、`FAILED` 或 `UNKNOWN`，单独展示，不改变边权或关系存在性。
- 直接工作关系（继续、实现、修复、依赖、修改、评审、交接、验证、取代）的边权高于调查或动机关系；置信度和执行阶段继续调整边权，不使用固定 0.70 门槛。
- 用户确认或拒绝不会改变推断来源类别；已拒绝关系不得因重新分析而自动恢复。
- 观察关系和 Jev 推断关系保留不同来源标记；候选线索不作为关系来源。

有向关系按各自的角色语义解释 A → B，不能统一假设 A 是较早的会话：

| 类型 | A → B 的准确含义 |
| --- | --- |
| `FORKED_FROM` | B 从 A 派生 |
| `SUBAGENT_OF` | B 是 A 的子代理会话 |
| `CONTINUES` | A 是前序会话，B 延续 A 的工作 |
| `IMPLEMENTS` | A 提出方案，B 落实该方案 |
| `FIXES` | A 记录问题，B 修复该问题 |
| `VALIDATES` | A 产出结果，B 验证该结果 |
| `INVESTIGATES` | A 记录问题，B 调查该问题 |
| `SUPERSEDES` | A 是旧方案，B 取代该方案 |
| `MOTIVATED_BY` | A 的发现或决定促使 B 的工作发生 |
| `DEPENDS_ON` | A 的工作依赖 B 的结果 |
| `MODIFIES` | A 修改 B 产生的交付物或决定 |
| `REVIEWS` | A 评审 B 的交付物或结果 |
| `HANDOFF_TO` | A 将工作交接给 B |
| `ALTERNATIVE_TO` | A 与 B 探索可替代方案；无向 |
| `RELATED` | A 与 B 存在具体工作联系但无法进一步分类；无向 |

无向关系的端点按稳定标识排序以去重。禁止自环；允许不同类型关系共存及跨多条关系形成的环路，不用 DAG 约束删除有效历史。结构边端点缺失时保留已知引用和诊断，不虚构父会话内容；跨项目引用不扩张为跨仓库关系图。

方向判断以各关系类型的端点语义为准，不通过比较会话创建时间替代判断；工作关系可发生在会话恢复期间。活动时间仅参与宽松候选排序。

Jev 请求材料来自候选会话当前可用的历史、总结、产物摘要和候选原因。程序验证响应的端点、类型、方向、分数范围和来源版本，不要求单独调用证据选择服务，也不以判断说明替代来源证据对象。TypeSafe 的 `Choice` 只返回受约束的选择与概率；界面将类型、方向、执行阶段和结果组合成可读说明，不声称该说明是模型生成的自由文本理由。

关系身份基于来源类别、规范化端点与类型保持稳定，与分析运行标识解耦。未知结果的内部去重状态绑定来源内容版本和 Jev 配置；来源或配置未变时不重复请求。确认记录保留对应判断版本；用户裁决不会自动迁移到不同类型或方向的新关系。

### 8. 候选生成与分析运行

模型分析必须由用户手动启动。候选发现先于 Jev 判断，不对全部会话组合逐一调用 Jev。候选语料跨项目覆盖所有可用历史；存在部分历史时仍可提名候选，Jev 可返回 `UNKNOWN`。

候选分层与数量：

| 层级 | 信号 | 范围与预算 |
| --- | --- | --- |
| 强 | 明确会话引用、共享产物 | 不因每会话候选配额截断；调用过多时分批处理 |
| 中 | 共享文件、相同分支名、最近更新时间接近 | 每会话中弱候选总额的保底层之一 |
| 弱 | 标题/预览词语重合、摘要与产物摘要的向量相似 | 可跨项目召回；每会话中弱候选总额的保底层之一 |

中层与弱层合计每会话最多 10 个邻居。每个有候选的层至少保留一个，其余名额按词面、结构、语义和时间综合强度分配。一个会话对同时命中多个信号时只计一次，并保留所有命中原因。跨项目共享文件、产物、分支名、活动时间、标题/预览词和向量相似都只召回候选，最终关系由 Jev 判断。

嵌入服务使用独立 OpenAI 兼容配置与凭据。为所有具有当前总结的会话和产物摘要生成向量，使用本机 SQLite 向量记录并做余弦近邻排序；语义候选不设相似度硬门槛。更新时间以 14 天半衰期乘入候选排序，不截断旧历史。索引记录绑定摘要/产物摘要版本、来源版本、规范化服务地址和实际模型；任一变化时重建对应向量。主题面板手动启动索引，向量请求最多每批 32 条输入；跨项目 Jev 关系每次手动运行最多处理 100 对，未处理候选保留供再次启动。

未知的 Jev 结果以候选、来源版本和 Jev 配置身份作内部去重；来源或配置变化后才重新判断。显式引用与共享产物候选不受每会话弱候选上限影响；每批调用上限仍按运行资源限制分批暂停，继续运行时不丢弃强候选。

Codex 总结与命名要求结构化最终输出；Jev 关系判断使用 TypeSafe 原生结构化答案，并在保存前验证关系类型、端点、方向、置信度、执行阶段和结果。

分析运行记录输入版本、模型配置、处理进度和失败情况；对相同输入复用有效结果。来源已变化时，迟到结果不得静默覆盖新结果。记录完整和部分内容覆盖状态，模型只解释已提供内容。

分析按总结、候选分类、分组与命名顺序处理；同一项目同一时间只有一个修改分析结果的运行。单个有效输出以事务提交，某一项失败不回滚此前成功项。

资源默认值：

- 项目分析启动前显示待总结会话数、候选判断数、待命名分组数、各阶段服务与模型及本批调用上限；关系材料会发送到所配置的 Jev 服务。全局索引在主题面板手动启动，并单独显示待索引会话、语义近邻和待判断跨项目会话对数量。调用数不冒充准确费用或令牌数。
- 默认每批最多启动 100 次模型调用，用户可在启动前调整为正整数。一个 Codex 回合或一次 Jev 推理 HTTP 请求各计一次；一个请求中的题目数另行统计，重试也占用调用额度。模型列表查询和缓存命中不算推理调用。
- 全部后端合计最多同时运行 10 次模型调用；每批总并发默认 2，可设为 1–10。临时故障默认自动重试 2 次，最多可设为 5 次；Jev 的 429、529 和临时网络故障按退避策略重试，遵守可用的 Retry-After。认证、明确额度不足或配置错误暂停运行，等待用户处理，422 等请求错误不盲目重试。
- 达到批次上限时进入可继续的暂停状态，未处理项保持待处理；用户继续时开启新批次。
- 每次调用默认最多等待 180 秒；可在分析设置中调整。超时按对应后端走取消流程，不把客户端超时当作远端已经停止。
- 已成功单元不因暂停或取消而丢失。确认取消后，迟到结果不得提交。
- 每次模型输入默认不超过 40000 个 Unicode 字符，可在分析设置中调整；Jev 包括 state 与所有题目文本。这不是令牌计数，也不保证满足服务端令牌限制。截断或抽样记录覆盖范围，不能宣称读取了未提供的历史。

总结与命名使用所选 Codex 的已配置模型；关系使用已验证的 Jev 配置。运行固定各阶段的配置版本，修改设置仅影响新运行；需要立即切换时先取消旧运行。凭据按目标服务隔离，修改 Base URL 不自动把旧服务密钥发送到新地址，须为新地址填写凭据。删除凭据会阻止后续 Jev 请求并取消其在途请求，不影响已保存结果。改变服务、实际模型版本或判定规则只使相关自动结果及依赖它的后续结果需要更新，人工裁决仍然保留。

运行状态为待执行、执行中、取消中、已取消、因额度或配置暂停、完成、部分完成和失败。界面区分已处理、成功、失败及尚未处理数量。

### 9. 工作流

工作流仍然是项目内围绕具体工作目标形成的会话分组。仅从观察关系和有效的 Jev 工作关系构建关系图；候选规则命中不直接成为边。Jev 关系按类型、置信度和执行阶段连续加权，再经过加权社区检测形成工作流；跨群边作为跨工作流联系保留。

每条会话至多有一个主要工作流；无关系或暂不能分组的会话进入“未分组”，仍在项目中可见。跨工作流关系不导致会话在多个时间线泳道重复出现。

用户可以重命名工作流，并把会话移至已有工作流或“未分组”。V1 不包含会话标题、标签、备注编辑，也不包含手工创建语义关系。

将用户改名与成员调整作为持久修正：改名只锁定名称，成员调整只锁定对应会话的归属；重新分析均不得覆盖。用户可显式选择恢复自动名称或自动归属，解除对应修正。

工作关系类型分为直接工作承接（继续、实现、修复、依赖、修改、评审、交接、验证、取代）和较宽联系（调查、动机）。聚类对关系类型、Jev 置信度和执行阶段使用连续权重，较具体、执行更深入且置信度更高的关系影响更强；`RELATED` 和 `ALTERNATIVE_TO` 保留展示但不合并工作流。发布前仍需用分层人工标注样本评估误合并，并据此校准工作流边权。

聚类继续使用固定种子和稳定排序的加权社区算法，使相同图和版本产生稳定结果。规则线索、主题相似或宽泛的 `RELATED` / `ALTERNATIVE_TO` 关系本身不能合并工作流。

算法分组完成后，先为新分组匹配稳定身份，再应用人工成员修正，保证每条会话至多一个主要工作流。新分组按成员交集最大优先匹配旧分组，一对一复用工作流身份；相同交集时按稳定工作流标识排序，无交集时创建新身份。保留用户命名但暂时无成员的工作流，以及仍被人工成员修正引用的工作流。

Codex 临时会话只为已形成的分组生成名称；Jev 不生成名称，也不决定全部成员。命名失败时保留分组并显示确定性的暂用名称，不隐藏整个工作流。

#### 9.1 全局主题

主题组独立于项目与工作流，可跨项目合并相同主题的会话，但不能修改项目身份或工作流成员。

- 使用全局受控主题词表；人工标注时可选择已有主题或新增主题名。每条会话只保留一个主要主题。
- Jev 根据会话总结与可用产物摘要，在词表中给出一个主题和分数。当前 0.45 为启动用初始门槛，低于门槛时会话保持未分类，只保留最高主题候选；人工校正样本会显示 Jev 建议一致率，但该便利指标不代表无偏的整体质量评估。
- 发布前需用每会话一个人工主题标签的代表性样本校准门槛，优化方向偏向减少漏掉同主题会话；主题标签与工作流成员修正分开存储。
- 用户可在全局主题视图中跨项目查看同一标签下的会话，并通过项目链接返回会话详情。主题标签不自动创建关系边。

### 10. 界面与运行状态

项目首页提供工作流导航和时间线，另提供关系图视图。会话详情包含来源元数据、回合、事实、总结和关系。关系详情展示来源类型、置信度、Jev 判断说明、执行阶段与结果，并提供可用裁决操作；不将 Jev 判断说明显示为来源证据。

提供独立的全局主题视图和词表管理。主题视图跨项目按全局标签显示会话，并保留项目来源导航；单会话详情显示主要主题与最高主题候选。嵌入服务设置与文本服务、Jev 设置分开，显示地址、模型、凭据状态、材料发送范围及索引状态。

首次尚未分析、没有会话、读取中、来源不完整、分析中、分析失败和缓存过期都应具有可区分状态，避免以空图表示所有情况。

项目内搜索覆盖会话标题、预览、会话标识与已生成总结。支持按工作流、工作区、归档状态与数据完整性过滤会话；全局主题面板单独支持跨项目主题筛选。关系视图支持按来源类别、关系类型、执行阶段、结果与置信度过滤。搜索与过滤不改写项目归属、来源事实或工作流成员。

时间线与关系图共享当前会话选择。过滤使已选会话不可见时保留详情并显示“被当前条件隐藏”的提示，用户可清除过滤。时间线支持日、周、月粒度及缩放；关系图支持平移、缩放、自动布局和节点选择。V1 不要求持久保存手工拖动布局。

界面使用中文表达领域概念，必要的来源标识、命令、路径和技术类型保持原样。

### 11. 分析后端、连接配置与隔离

V1 交付 `CodexEphemeralAnalyzer`、`JevRelationAnalyzer` 与独立的 OpenAI 兼容嵌入适配器。前者复用用户已配置的 Codex 负责总结和工作流命名；Jev 负责关系类型、方向、执行阶段、结果和主题判断；嵌入适配器负责生成语义检索向量。保留按能力替换的领域接口，不把 TypeSafe 当作 OpenAI Chat Completions 兼容接口，也不在 Jev 失败时静默改用其他模型判断关系。

**Jev 配置与调用：**

- 应用提供单个全局 Jev 连接配置，用户填写 API Key、Base URL 和模型 ID。Base URL 默认提示 `https://api.typesafe.ai`；模型默认 `jev-latest`，允许手动填写版本化 ID。保存配置不会自动运行项目分析。
- Base URL 是服务根地址，可含网关路径前缀；统一处理末尾斜杠，再追加 `/v1/models` 或 `/v1/systemone`。不接受已包含这两个端点或重复 `/v1` 的填写方式，给出修正提示；不静默换成其他服务地址。正式连接使用 HTTPS，本地开发测试可使用回环 HTTP；拒绝 URL 用户信息、查询串和片段，不跨源转发认证重定向。
- 后端使用 `Authorization: Bearer <API_KEY>`，通过 `GET /v1/models` 验证连通性并列出可用名称。模型列表目前可能只含别名，不能仅因版本化 ID 未被列出就判其无效；列表连通成功也不能冒充模型推理成功。
- 单独的“测试推理”操作可发送固定合成材料到 `POST /v1/systemone`，提前显示会消耗一次推理调用，绝不使用项目历史。真实请求使用 `state`、`model`、`questions`，记录响应实际模型 ID 和用量。配置错误时保留事实浏览和已有结果；单独的 Codex 总结与命名不依赖 Jev 密钥。
- API Key 保存到操作系统凭据库（macOS 钥匙串、Windows Credential Manager），不进入 SQLite 明文、项目文件、前端持久存储、日志、错误详情或分析材料。UI 仅显示已配置状态，支持替换与删除；后端不提供读回明文密钥的查询接口。系统凭据库拒绝访问或写入失败时给出可操作错误，不退回明文存储。
- 区分地址无效、未配置、连接失败、认证失败、模型/协议不支持、限流、服务过载、额度不足、请求无效、超时与凭据存储失败。诊断内容脱敏；仅根据实际状态和结构化响应解释错误，不把所有 429 都说成余额不足。
- Jev 调用只是 HTTP 决策请求，不启动或恢复 Codex 会话、不执行来源材料中的指令或工具。取消时停止排队与重试，终止客户端请求并拒绝迟到结果；确认本地请求任务结束后显示已取消。当前官方契约没有远端取消接口，界面不承诺远端计算或计费已停止。
- 别名可能漂移；结果保存请求模型名称和响应实际版本，发布质量评估固定版本化 ID。使用别名时，在用户启动的新批次中以固定合成探测确认实际版本，并计入预算，再固定该批次版本；无法确认时暂停需要版本一致性的分析，不能将旧别名缓存视为新版本结果。

**嵌入服务配置与调用：**

- 用户单独填写 OpenAI 兼容服务地址、嵌入模型 ID 和 API Key；凭据保存在操作系统凭据库（macOS 钥匙串或 Windows Credential Manager），地址和模型保存到应用设置。嵌入服务独立于文本服务和 Jev，修改其中任一配置只使向量索引及依赖它的候选失效。
- 通过固定合成文本验证 `POST /v1/embeddings`，检查响应模型、返回向量数量、维度及有限浮点值；测试不发送项目材料。真实向量请求的材料范围为当前有效的会话总结和产物摘要，索引前在全局主题面板显示待处理数量。
- 向量与规范化地址、请求模型、响应实际模型、摘要内容版本和来源版本绑定。不同维度或模型的向量不能参与同一相似度比较。
- 向量请求按最多 32 条输入分批并支持本地取消；每次全局索引中的主题归属与跨项目关系判断共用最多 100 次 Jev 推理调用，使用模型别名时的固定版本合成探测也计入上限。未处理的归属与候选对保留供下次手动启动继续。文本分析与全局语义索引分别手动启动，并使用独立调用上限。

**Codex 临时分析隔离：**

使用 `thread/start.ephemeral` 创建临时分析会话，并用 `turn/start.outputSchema` 请求结构化最终消息。仅成功终结且结果通过本地模式与证据验证的回合可以提交分析结果。

来源读取与每次分析运行使用独立受管进程，便于分析取消时保持来源浏览及其他运行可用。临时会话标识同时进入应用排除集合；其不落入普通可枚举历史的行为必须经过真实适配器验证。

分析以只读沙箱、关闭工具网络访问和可用的最小工具配置运行，不批准模型额外提出的权限或外部动作请求，不修改用户已有会话及持久 Codex 配置。历史消息、命令输出和文件片段只作为分析材料处理。

已核验协议没有统一关闭全部工具的顶层参数。临时会话、结构化输出和只读沙箱均不构成“绝不执行任何工具”的证明；不得发明参数声称实现此保证。上线前必须验证实际配置不会写入项目、触发外部动作或污染普通历史。若无法满足上述副作用边界，保留事实浏览并禁用该分析配置，而不静默放宽限制。

Codex 取消使用 `turn/interrupt` 并携带实际临时会话与回合标识。收到中断请求响应后仍显示取消中；确认 `interrupted` 等终态后显示已取消。若进程未响应，可终止专用于分析的受管进程，确认退出后标记取消。整个取消过程中不得接纳迟到的结果；不能把这一协议终态要求套用于 Jev HTTP 请求。

### 12. 应用接口与错误契约

Tauri 接口承载领域请求与响应，不向前端透传 app-server 方法、游标或传输对象。公开能力包括：

| 操作 | 可观察结果 |
| --- | --- |
| 查询来源状态、选择 Codex 二进制 | 版本、元数据与历史能力、连接状态、可恢复错误 |
| 保存、验证或删除 Jev / 嵌入服务配置 | 服务地址、模型名称、凭据已配置状态、连接/推理分别验证的结果；不返回密钥明文 |
| 列出和打开项目 | 本地项目身份、工作区、来源依据、已有索引状态 |
| 刷新或取消索引 | 运行标识、进度、完整性和最终状态 |
| 查询项目视图、会话与证据 | 分页的领域视图、内容版本与数据质量 |
| 查询全局主题、维护主题词表、修正人工主题标签 | 跨项目主题组、会话主要标签及持久化的人工标注 |
| 读取或重建语义索引 | 向量模型身份、来源版本、索引进度与错误；不返回密钥 |
| 预览、启动、继续或取消分析 | 本批预算、运行标识、进度、缓存复用与最终状态 |
| 确认、拒绝或恢复待裁决关系 | 持久裁决及新的关系修订号 |
| 重命名工作流、调整成员或恢复自动状态 | 持久修正及新的项目视图版本 |

后台索引和分析通过带运行标识的事件报告进度；UI 可重新查询运行状态，丢失一个事件不应造成永久卡死。

保存关系裁决和工作流修正时提供预期修订号；过期修改返回冲突并要求刷新，不用旧页面状态覆盖较新的用户操作。

错误包含稳定错误码、中文消息、是否可重试及是否保留缓存。至少区分二进制不可用、协议不兼容、来源读取失败、内容不完整、项目归属冲突、Jev 连接/凭据配置问题、分析认证或额度问题、限流和过载、结果验证失败、存储失败、迁移失败、并发修改冲突与取消失败，并标明对应后端。

## 测试决策

用户已确认以核心应用服务的公开行为作为主要测试边界，辅以 Codex 与 Jev 适配器契约测试及桌面用户流程测试。分析器结果验证纳入核心服务及适配器契约，不另建平行的产品测试入口。当前仓库没有可复用的业务代码或测试先例。

| 测试边界 | 主要可观察行为 |
| --- | --- |
| 核心应用服务 | 项目归属、索引幂等、部分失败、关系与证据、时间完整性、裁决持久化、工作流成员、资源限制、重试与过期结果 |
| Codex 与 Jev 适配器 | Codex 初始化、历史兼容、临时结构化输出与中断终态；Jev URL/认证、原生问题与答案、模型版本、错误/重试、HTTP 取消及密钥不泄露 |
| 桌面流程 | 选择项目、配置与测试 Jev、查看结构关系、手动分析、查看证据、关系裁决、时间线与关系图定位 |

测试使用脱敏或合成数据，不把真实用户历史变为仓库测试材料。自动化测试不依赖真实模型给出确定答案。算法参数和具体模块内部组织不作为行为断言。

至少覆盖以下验收场景：

1. 包含已归档会话与子代理的完整列表能被发现且不重复。
2. 任一分页中途失败时，已有会话与关系不被错误删除。
3. 一条会话隔日恢复时，时间线保留中间空档。
4. 部分回合缺失时间时，只显示已知活动及其不完整标记。
5. 模型返回 `NONE`、未知、无效端点或类型/方向不匹配时，不产生工作流边；未知仅作版本化内部去重。
6. 用户拒绝一条关系后重新分析，该关系保持拒绝。
7. 较早创建、较晚恢复的会话产生后续工作时，系统不只凭创建时间否决关系。
8. 模型分析失败时，项目事实、结构关系和先前有效结果仍可查看。
9. CodexFlow 自身分析不会作为新项目工作再次进入索引。
10. 同一仓库的 worktree 合并，独立克隆及嵌套仓库不被误合并。
11. 一条会话至多占用一个工作流泳道，跨工作流关系仍然可见。
12. 用户改名、移动成员后重新分析，人工修正保持有效；用户显式解除后可恢复自动结果。
13. 达到调用上限时暂停，继续只处理剩余项；取消中的迟到结果不会提交。
14. Codex 中断请求已响应但回合尚未结束时，界面保持取消中；Jev 以本地请求结束确认取消，不伪造远端终态，两种后端均拒绝迟到结果。
15. 应用重启后缓存、裁决及工作流修正保持；中断的运行不会被误认为完成。
16. 迁移失败及旧应用打开新格式数据时，不破坏原数据。
17. 无向关系反向输入正确去重，结构关系和因果关系遵循统一端点语义。
18. 过滤和视图切换不改变会话身份及人工数据。
19. 首次未配置、无效密钥、错误服务地址或系统凭据库不可用时，能修正配置并分别验证 Jev、文本与嵌入服务连接/推理；事实浏览及单独 Codex 总结仍可使用。
20. 保存、重启、轮换和删除各服务凭据后，秘密不出现在数据库、日志、前端持久存储或错误中；修改服务地址不会把旧密钥自动发送到新服务。
21. Jev 返回 NONE、未知、低置信度或证据不足时分别正确呈现；执行阶段、结果、类型与方向分别解析；候选外证据不入图，中文和混合技术文本可进入质量评估。
22. 项目关系判断沿用分析批次预算；全局嵌入索引与主题/跨项目关系判断通过主题面板手动启动，共享每次最多 100 次 Jev 推理调用，并报告调用和待处理数量。配置或摘要版本变化正确使相关向量、候选和判断失效；取消和设置变更不能让旧结果覆盖新运行。
23. 跨项目向量检索保留强候选，不设语义硬门槛；每会话中弱候选不超过 10 对且每个有候选的层至少保留一对。
24. 主题词表跨项目统一；每条会话至多一个主题，低于主题门槛时未分类并保留最高主题候选。

真实 Codex 冒烟测试另行验证来源读取、临时总结/命名、结构化结果、中断终态及分析隔离；真实 Jev 冒烟另行验证所配置端点的认证、模型查询、固定合成判断、实际模型版本及取消后的本地状态。两者均使用受控数据与配置，不将用户现有会话作为自动测试写入对象，不把用户密钥放入测试材料。

### 规模与性能验收

用户确认的单项目规模为 500 条会话、1 万回合、10 万条目。这是验收数据集规模，不是超过规模后拒绝打开的硬上限。

性能验收门槛：

- 统一使用 16 GB 内存的 Apple Silicon Mac 基准环境，记录具体型号、系统与应用构建版本；开发构建不作为正式性能结论。
- 缓存已建立时，项目概览首次可交互不超过 2 秒。
- 500 个节点、最多 3000 条可见关系的图完成初始布局与可交互渲染不超过 5 秒。
- 本地会话查询、过滤及证据首屏查询的第 95 百分位响应时间不超过 500 毫秒；大段内容分页，不能一次装载全部条目到界面。
- 缓存场景连续执行至少 20 次测量并报告分布；同时记录首次启动，避免仅以热缓存结果代替冷启动体验。
- 本地数据库与合成适配器固定输入用于验证内部性能。真实 app-server 读取及模型调用分别记录延迟、进度和失败率，不把外部服务时延计入本地响应保证。
- 索引和模型运行期间桌面视图仍可交互并接收取消操作，不在 UI 主线程执行索引或聚类。

### 模型结果质量验收

建立两类经人工标注的真实数据。工作流关系样本按强、中、弱候选层级及跨项目范围分层抽取，标注无关系、无法判断、正确类型与方向、执行阶段及结果；阈值以优先避免误合并为目标。主题样本为每条会话标注一个全局主题，主题词表允许人工维护；单独校准主题门槛并优先提高召回率。校准结果与保留验证样本分开报告，固定嵌入模型、Jev 模型、端点、摘要版本及问题规则。少样本结果不宣称代表全部实际项目。

评估至少报告工作流关系精确率/召回率、主题归属召回率、未分类比例、各关系类型/阶段样本量、嵌入候选召回率及候选调用量；不得用全部拒绝关系或全部未分类规避质量验收。当前不预设统一 0.70 或固定准确率门槛，门槛由标注结果按已确认的精确率/召回率偏好校准。

## 范围边界

V1 不包含多人协作、云同步、GitHub 拉取请求全量集成、事项跟踪系统、自动写项目文档、跨仓库关系图、实时代理编排，以及代替用户操作原有 Codex 会话。

本轮已确认不将 Linux、SSH 主机和多个 Codex 数据目录纳入 V1 正式验收。Windows 正式支持范围限于 Windows 11 x64。

### Windows 11 x64 支持与分发

- Windows 版通过 `PATH` 自动发现 Codex CLI，兼容 `codex.exe` 与 `codex.cmd`；不显示手动可执行文件路径选择。Codex 数据目录默认是 `%USERPROFILE%\.codex`，`CODEX_HOME` 优先覆盖默认值。
- 文本服务、Jev 与嵌入服务的 API Key 保存到 Windows Credential Manager。凭据库读写失败时不得保存为 SQLite、配置文件或其他明文副本。
- 首批下载包为 NSIS 单文件 `.exe`，不要求 Authenticode 签名。安装器由用户选择当前用户或全机安装；NSIS `both` 模式会在启动时请求管理员权限，即便最终选择当前用户安装。
- Windows 11 缺少 WebView2 Runtime 时可从网络获取 bootstrapper；不把离线安装器作为必需条件。首批通过 GitHub Release 或直接下载手动提供；暂不配置 Windows GitHub Actions。
- Windows 发布前需在 Windows 11 x64 上完成原生 Rust/Tauri 构建、相关 Rust 与 UI 回归，并安装和启动生成的 NSIS 安装包。对应逐项证据记录在 [Windows 11 x64 验收记录](release/windows-11-x64-acceptance.md)。

会话标题、标签和备注编辑，手工创建关系，持久手工布局、独立 OpenAI API 后端与本地模型后端均不在本 V1 交付范围。TypeSafe Jev 原生 API 关系后端属于本次明确增加的 V1 范围；V1 不扩展为通用模型供应商管理平台。原有 YAML 用户数据迁移不自动纳入本规格。

旧规格中的 Python 服务、HTTP 应用接口、YAML 作为唯一存储、纯人工关系和以创建至更新时间为活动时间线的方案，均不沿用为新 V1 架构。
