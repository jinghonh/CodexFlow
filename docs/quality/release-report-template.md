## 逐项核对

从 `report.json` 核对每对的候选、两阶段 Choice confidence/probabilities、请求与实际模型版本、证据选择、机械证据有效性及错误；将全部异常及对应样本编号列在这里。任何样本未完成或有效关系机械检查失败时，不填写通过结论。

| 检查项 | 结果与样本编号 |
| --- | --- |
| 样本全部完成人工确认、输入摘要未变 | 待填写 |
| 候选漏检、模型 `NONE`、无法判断、证据不足、低分 | 待填写；分别给出分子和全部样本分母 |
| 默认展示的所有有效推断边机械证据检查 | 待填写 |
| 单项错误、暂停、取消、重试、版本不一致 | 待填写 |

## 质量指标

| 指标 | 分子 / 分母 | 结果 | 门槛 |
| --- | --- | --- | --- |
| 默认展示关系的人工认可准确率 | 待填写 | 待填写 | ≥ 90% |

按 `quality-summary.json` 的 `byGroup` 逐类补充各场景与语言的样本数、可判定正例分母、展示边数、认可边数和召回正例数。单独解释 `NONE` 与人工证据不足的处理，不把后者计为确定负例。列出任何已知质量缺陷、修复提交和重新评测版本；人工标签及验收门槛不得事后更改。

## 结论与限制

填写本次冻结合成样本是否达到 #11、#32 的质量门槛。说明样本规模、单次模型评测、每对独立候选环境以及与真实项目邻居竞争不同的限制；不得把本次结果外推为全部实际项目的准确率。保留 `lock.json`、`report.json`、`quality-summary.json` 与所用冻结输入，以供复现。
