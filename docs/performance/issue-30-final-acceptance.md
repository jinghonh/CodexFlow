再验收发现一个超规模功能错误：增加第 501 条会话导致候选缓存失效，正式包并发计算图、工作流和候选时曾显示 `STORAGE_FAILED：保存规则关系和候选清单失败`。在同一隔离数据库上用四个并发核心调用复现为 **2 成功、2 失败**；单独顺序调用成功，指向 SQLite 延迟事务读后升级写锁时的并发冲突。候选版本检查和保存现改用即时事务，先取得写锁再检查来源版本。修复后四个并发调用 **4/4 成功**；对可丢弃的固定输入运行 `performance race-candidates DIR` 也为 **4/4 成功**。重建后的 501 条正式桌面路径没有该错误，候选视图显示 2500 对。回归程序会修改传入目录，必须对生成数据的副本运行：

```sh
cp -R /tmp/codexflow-issue30-e815193-v1 /tmp/issue30-candidate-race-new
cargo run --release -q -p codexflow-core --example performance -- race-candidates /tmp/issue30-candidate-race-new
```

已运行受影响检查：`cargo test --locked -p codexflow-store`（24 项）、`cargo test --locked -p codexflow-core candidate`（8 项）、上述四路并发检查、正式 Tauri 构建与 `cargo fmt --all`。本次正式包的真实来源单独记录为：机器上有 `codex-cli 0.150.1`，但隔离测量包仍指向故意无效的二进制路径，未读取真实 Codex 历史，故无真实来源时延。Jev 在隔离包中未配置密钥，真实模型时延与分析期间取消均无数据；合成来源取消不能代替它们。

检查器尝试：正式包的“视图”菜单只有全屏操作，常用检查器快捷键没有打开性能面板。下一步若要重新判定被暂缓的响应门槛，需要在正式桌面路径内记录从用户操作到结果绘制的时间，再做至少 20 次缓存测量，并给首次概览设置应用内可交互标记；当前外部操作计时无法替代这些标记。用户已允许性能测试确实无法通过时先跳过，以上暂缓项均未计作通过，#30 仍应保持开放。

## 结论与范围

本次从 `origin/master` 的 `e8151934360cfdd27084ce3c15e26b31b722fefd` 建立独立分支，在 16 GiB Apple Silicon Mac 上用正式桌面包复测 `issue-30-v1`。独立审查指出 Worker 失败后排队的主线程布局不能取消；修复并重建后，目标图的 20 次桌面操作观察均低于 5 秒。实际用户路径中还修复了大列表阻塞、WebKit 布局 Worker 失败及启动索引命令崩溃。核心接口的查询、过滤、证据首屏 20 次第 95 百分位均低于 500 毫秒。

**#30 尚不能标记全部验收通过。**新包第一次启动的计算机操作计时高于 2 秒，第二次低于 2 秒；该计时混入应用定位和可访问树采集，尚不足以判定应用自身的首次交互门槛。桌面操作计时也不能分离出会话查询、过滤、证据首屏的端到端第 95 百分位。真实 Codex 来源和 Jev 模型服务的时延与模型分析取消未测；大图采用视口内绘制，未测全部 2999 条边同时出现在同一视口的绘制。以下分别报告已经观察到的结果和边界。

## 正式桌面观察

审查后新包退出进程后首次打开：从请求打开至窗口可见 **4092 毫秒**，至已缓存项目概览显示“500 条会话”、搜索框可点击并完成点击 **4917 毫秒**。再次退出进程、重新打开：对应为 **816 毫秒**和 **1642 毫秒**。这是计算机操作接口的经过时间，包含应用定位、启动、可访问树采集和自动点击开销；第一次的 4917 毫秒不能作为应用自身超过 2 秒的证明，第二次的 1642 毫秒也不能替代第一次。首次看到搜索框时列表仍显示“正在查找会话”，所以这些数字仅证明概览和搜索输入已可操作，并不证明全部列表已完成查询。审查前旧包的一次对应记录为 1007 毫秒和 1910 毫秒，只适用于旧包。

在审查后新包里，从时间线切换到关系图 20 次。每次重新挂载关系图、重新调用项目图查询，等待“关系图布局完成”及“2999 条可见关系”出现在可访问状态，且确认没有布局失败提示。点击前至状态确认的分布：最小 **1.433 秒**，中位 **1.451 秒**，第 95 百分位 **1.490 秒**，最大 **1.514 秒**；20 次均小于 5 秒。计时包含计算机操作及可访问状态采集开销。500 个节点和 2999 条关系仍在图数据中；大图先绘制当前视口，平移、缩放后显示其余部分，未强制把所有图元同时挤进屏幕。审查前旧包的中位数 1.466 秒、第 95 百分位 1.635 秒不用于新包结论。

审查前旧包的桌面真实操作还核验了 `perf-thread-0250` 搜索只返回匹配会话；打开历史后首屏为 20/20 回合、10/10 条目与 1/1 结构化事实；证据定位能回到来源。审查后仅改动图布局取消路径，未重复这些功能操作。旧包的计算机操作计时混入自动化及可访问树扫描，不能据此宣称桌面端到端查询第 95 百分位小于 500 毫秒。

审查前旧包的后台索引使用独立的合成 Codex 适配器夹具验证：索引运行时桌面仍可输入搜索并点击取消；运行 `index-1790232511476-21627-2` 的持久化状态为 `cancelled`，起止时间相差 1.479 秒，尚未保存页面。夹具在 `thread/list` 等待时由用户界面取消，证实索引取消路径接受操作。这不是实际 Codex 来源或 Jev 模型调用的时延。测试结束后将隔离应用数据库还原为固定数据集。

## 实际路径修复与正确性

原集成包在 500 会话、密集工作流同时挂载时产生大量卡片和关系行，首次图切换约 38 秒。现在项目会话、工作流成员、内部关系、未分组会话和跨工作流关系每次显示 40 条，可继续加载；过滤与联动仍使用完整结果集，没有裁掉数据。关系图在大图时绘制视口内图元，并允许平移和缩放。筛选变化时终止旧布局 Worker；Worker 失败后等待动画帧的主线程回退也会随筛选变化取消。即使旧帧回调被触发，进入布局前仍检查取消状态；模块加载前后同样检查，避免过时布局阻塞界面。

原先同步的 `start_index_run` Tauri 命令在桌面事件线程调用 `tokio::spawn` 导致进程中止；改为异步命令后，上述后台索引、搜索与取消路径完成。索引仍由核心已有异步任务执行。回归覆盖大列表继续加载、搜索末尾会话、Worker 回退、筛选取消旧 Worker，以及 Worker 已失败但回退已排队时的取消。新包重新完成 20 次桌面图布局测量；其他桌面功能核验对应审查前旧包。

超过本次验收规模未设置拒绝打开的硬限制，但响应与绘制性能尚未测。真实来源和模型调用需要单独报告；本次固定输入结果不包含它们。
