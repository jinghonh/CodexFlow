## 复现

以下命令中的目录必须是全新、可丢弃的路径。要复现本文记录的历史结果，先检出 #30 候选提交 `41a2742a18045f46017057654e7c60d4f072eded`；在当前集成提交运行这些命令属于新的测量，不能与历史结果混作同一构建。

```sh
npm ci
cargo run --release -q -p codexflow-core --example performance -- generate /tmp/codexflow-perf-issue30-v1
cargo run --release -q -p codexflow-core --example performance -- measure /tmp/codexflow-perf-issue30-v1 20
cargo run --release -q -p codexflow-core --example performance -- export-graph /tmp/codexflow-perf-issue30-v1 > /tmp/codexflow-perf-graph.json
node scripts/measure_graph_layout.mjs /tmp/codexflow-perf-graph.json 20
npm run tauri -- build --config '{"identifier":"dev.codexflow.performance","productName":"CodexFlow Performance"}'
```

测量程序沿公开核心接口调用项目目录、项目会话、时间线、关系图、工作流、候选、会话查询与过滤，以及回合、条目、事实首屏分页。单次查询最多读取对应分页；它核对数据库三张主表的行数与图可见关系数。布局脚本对公开关系图结果使用桌面端相同的 ELK 参数及结构骨架选择，计时仅覆盖 ELK 布局，未包含 Worker 加载、React Flow 或 WebView 绘制。

## 修复与验证范围

- 项目归属核对在一次重算内复用相同工作目录的规范路径和 Git 解析结果，避免 500 条会话逐条启动 Git 子进程。
- 候选与规则关系在输入版本未变化时复用数据库缓存；输入版本包含项目会话、来源内容修订、事实规则与候选规则。失效或存在旧候选时重新生成并保留既有正确性检查。
- 关系图在 Worker 中执行 ELK。分层布局仅以来源优先的生成森林确定位置，仍将全部关系传入图组件；快速切换过滤时取消旧 Worker。筛选后的边在重新布局前立即更新。
- 桌面桥接将会话查询、关系图、工作流、候选预览与时间线查询交给阻塞任务池执行，避免这些同步数据库和聚类工作占用 Tauri 的事件处理线程。
- 时间线初始展示 40 条会话，可继续分页浏览；具体回合、条目和事实仍由现有公开接口分页读取，不把 10 万条目装进 UI。
- 本次 #29 与 #30 集成候选通过 `cargo test --locked -p codexflow-core -p codexflow-store`（核心 78 项、存储 24 项）、`cargo check --workspace --all-targets --locked`、`cargo fmt --all -- --check`、`npm run test:ui`（9 个文件、38 项）和 `npm run build`。回归检查覆盖缓存命中与失效、SQLite 恢复、查询错误时保留详情、关系刷新失败时保留旧图、密集图保留全部边，以及时间线分页。前端构建提示图布局相关 JS 分块超过 500 kB；正式桌面性能门槛仍须实机测量。

## 待完成的桌面验收

历史 #30 候选的正式桌面应用已构建，基准应用数据与用户原有应用标识隔离。此机器在执行桌面操作时处于锁屏状态，计算机操作接口返回“Mac is locked and automatic unlock could not unlock it”。因此尚未测量该候选应用首次打开至概览可交互、WebView 中的 500 节点与 2999 边完整绘制、后台索引或分析时的交互与取消；集成 #29 后的当前代码也没有新的正式桌面构建测量。上述门槛不能仅凭核心与 ELK 独立结果宣称通过。解锁后应在空闲机器上对当前集成提交生成正式包，沿真实桌面操作路径完成至少 20 次缓存测量和一次完整冷启动记录。

真实 Codex 来源读取与 Jev 模型服务未用于固定输入测试，也没有被计入本地响应指标；其延迟、进度和失败率需在具备受控来源与服务配置时另报。超过本数据集规模没有写入硬上限，性能范围尚未测量。
